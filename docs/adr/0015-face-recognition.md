# ADR-0015: Распознавание людей по лицам

Статус: Accepted (владелец продукта, 2026-09-30)

## Контекст

Типичный сценарий — фотосъемка события (премьера фильма): в архиве много фото известных людей, и администратор хочет
находить фото конкретного человека. §4 ТЗ исключает из MVP «распознавание личности» и «face clustering»; это решение
владельца продукта снимает запрет в рамках, описанных ниже. Prompt VLM по-прежнему не называет людей (ADR-0010):
идентичность определяется только отдельным контуром лиц по справочнику, заполненному администратором.

## Решение

### Модель

InsightFace `buffalo_l` (релиз v0.7): детектор SCRFD-10G (`det_10g.onnx`) и распознаватель ArcFace R50, обученный на
WebFace600K (`w600k_r50.onnx`), через onnxruntime на CPU. Лицензия моделей — только некоммерческое использование;
владелец подтвердил некоммерческое использование. Выбор: стандарт де-факто, LFW ≈ 99.8%, 30–125 мс на фото на CPU
Mac, работает параллельно с Qwen на MPS (onnxruntime не использует MPS). Пакет `insightface` не нужен (требует
компиляции): декодирование SCRFD и выравнивание по 5 точкам реализованы в `services/ai/app/models/faces.py`.
Версия модели (`revision`) — префиксы sha256 обоих файлов; векторы разных версий не сравниваются (§77).

Замер (2026-09-30): 21 фото + 8 фото пользователя с события — один человек 0.64–0.87 (в т. ч. в профиль), разные люди
≤ 0.15; на пейзажах и интерьерах ложных лиц нет. Пороги ниже настраиваются.

### Разделение ответственности (инварианты `.agents`)

- **AI service** находит лица и считает векторы: `POST /v1/faces/detect` → лица с bbox (доли размера изображения),
  score, 5 точками и L2-нормированным 512-мерным вектором. Людей, имен и ID не знает, в БД не ходит.
- **Backend** хранит лица и справочник людей, сопоставляет векторы, решает, чье лицо. Отдельный этап обработки
  `faces` после `ai_analysis`: повторяемый и идемпотентный; ошибка этапа не мешает тегам и поиску.
- Имя человека назначает только администратор (как canonical tags).

### Модель данных и поведение (backend, этап 2; уточнено владельцем 2026-09-30)

Сценарий владельца: «загружаю 10 фото друга → система находит его лицо и предлагает запомнить → я пишу имя →
дальше все фото с ним подписываются автоматически». Модель не переобучается: «запомнить человека» — сохранить векторы
его подтвержденных лиц как эталоны.

- Поиск лиц — отдельная задача очереди `images.ai` после финализации фото (не этап `processing_tasks`): сбой лиц не
  делает фото `failed`, машина состояний обработки не меняется. Повторно для того же изображения и revision не
  выполняется; reprocess только заново сопоставляет лица.
- `people`: id, name, note. `faces`: image_id, bbox (доли), размер в px, score, embedding vector(512), model_revision,
  person_id, status, similarity, rejected_person_ids.
- Статусы лица: `unassigned` — не знаем; `suggested` — похоже на человека (cosine ≥ `FACE_MATCH_THRESHOLD`, 0.40),
  ждет подтверждения; `auto` — уверенное совпадение (≥ `FACE_AUTO_ASSIGN_THRESHOLD`, 0.55) — подписано
  автоматически; `confirmed` — подтверждено администратором, **эталон** человека. Эталоны — только `confirmed`
  (`auto` не становится эталоном, чтобы ошибки не накапливались).
- Отклоненное администратором совпадение запоминается (`rejected_person_ids`) и больше не предлагается.
- **Незнакомые люди:** неназначенные хорошо видимые лица (≥ 64 px) группируются по сходству (≥ 0.45); группа,
  встреченная хотя бы на 2 фото, предлагается как «новый человек». Администратор снимает лишние лица и вводит имя:
  лица становятся `confirmed`, после чего все прочие лица заново сопоставляются.
- Фото человека — лица `auto` и `confirmed`: фильтр галереи по человеку, имена людей участвуют в поиске по словам.

### 152-ФЗ

Вектор лица, по которому узнают человека, — биометрические персональные данные. Владелец продукта отвечает за
правовое основание (согласия). Система обеспечивает:
- доступ к лицам и справочнику только у администратора;
- **удаление человека вместе с биометрией**: удаляются его эталоны и все векторы лиц, привязанных к нему
  (изображения остаются);
- возможность отключить контур лиц настройкой (`FACES_ENABLED=false`) без влияния на остальную обработку.

### Этапы

1. AI service: модель, `POST /v1/faces/detect`, контракт AI API 1.9.0.
2. Backend: задача поиска лиц, `people`/`faces`, сопоставление, группы незнакомых лиц, API, удаление биометрии,
   фильтр и поиск по человеку (контракты 1.10.0).
3. Админка: раздел «Люди» (новые люди, справочник, подтверждения), лица на фото, фильтр по человеку.
