# Решения для утверждения контракта MVP

**Статус: утверждено владельцем продукта 2026-09-25; ADR-0001–0011 — Accepted.**

1. **ADR-0001 — вход.** Sanctum SPA cookie-сессия через один origin (Nuxt, `/api`, `/sanctum` за nginx); CSRF для изменяющих запросов. Ошибки 401/403/419, неверный логин — 422. Долгая сессия `remember` в MVP не нужна: убрать предложенное поле из login. Поиск и media требуют сессию администратора.
2. **ADR-0002 — формат API.** Одиночный ресурс — объект; список — `{data, meta:{page, per_page, total, last_page}}`. `page=1`, `per_page=50`, максимум 100 (для tags 500). Сортировки и фильтры — только явно перечисленные в текущем OpenAPI; дополнительные `original_name`/`file_size` пока не нужны. Ошибки и `X-Request-ID` — по ADR.
3. **ADR-0003 — dashboard/retry.** Отдельные `GET /api/admin/dashboard` и `POST /api/admin/images/{id}/retry`. Retry только для failed image, продолжает с упавшего этапа. Batch-level retry в MVP не добавлять; reprocess сохраняет отдельную семантику.
4. **ADR-0004 — поиск.** Поле `mode` обязательно. Несколько tag IDs соединяются через AND; дочерние теги автоматически не включаются. Порог similarity не вводить. `debug` доступен любому вошедшему администратору; теги остаются жёстким фильтром для hybrid.
5. **ADR-0005 — batch/upload.** `total` считает сохранённые изображения без дублей; `processed = ready + failed`; batch `failed`, когда все сохранённые изображения failed. Retry возвращает batch в processing. Форматы JPEG/PNG/WebP, лимит загрузки 50 MiB, поле `image`, ответ 201. AI получает уменьшенную копию в пределах своего лимита 20 MiB; оригинал остаётся неизменным. Политика AI: первая попытка + 3 повтора через 10/30/120 секунд. Совпадение SHA-256 с soft-deleted изображением возвращает 409; автоматического закрытия batch без вызова complete нет.
6. **ADR-0006 — ручные правки.** PATCH image меняет только `original_name`. Удаление любого назначенного тега создаёт suppression; повторное добавление снимает его. Отдельный экран/endpoint просмотра suppressions в MVP не нужен.
7. **ADR-0007 — теги и aliases.** Нормализация NFKC + Unicode lowercase + схлопывание пробелов, `ё` сохраняется. Alias уникален глобально и не пересекается с canonical name другого тега. Одинаковые canonical names разных типов допустимы; при выборе сначала учитывается тип concept, при неоднозначности создаётся кандидат. Совпадение с архивным тегом не создаёт нового назначения или кандидата.
8. **ADR-0008 — модерация.** Повторно обнаруженный rejected candidate остаётся rejected, но счётчик обновляется. Merge по умолчанию создаёт alias. Назначения изображений после approve/merge имеют `source=ai`, `locked=false`, так как понятия обнаружены AI; suppression учитывается. Добавить `resolved_tag_id` в `tag_candidates` для аудита результата решения администратора.
9. **ADR-0009 — embeddings.** AI возвращает фактические ревизии моделей; для локальных весов revision — стабильный digest файла/набора весов. `model_key` — имя модели без префикса организации. Векторы L2-нормализованы. Активная версия задаётся в Laravel; поиск не смешивает версии. Unique для tag embeddings включает `tag_id + model_key + model_version`.
10. **ADR-0010 — AI service.** `/health` проверяет живой процесс, `/ready` — загруженные модели. Service key передаётся через `Authorization: Bearer`. Concept type совпадает с типами тегов; неизвестный тип отображается в `other`. Labels — на английском (с 2026-09-29, contracts 1.3.0 — caption и labels на русском). Лимиты: 20 MiB и 50 MP для analyze, до 64 текстов по 1000 символов, до 50 concepts. `MODEL_OUTPUT_INVALID` возвращает 502 и может повторяться.
11. **ADR-0011 — media.** Cookie-сессия + nginx `X-Accel-Redirect` через внутренний путь `/_protected/`; вне Docker допустим PHP fallback с тем же клиентским URL. `Cache-Control: private, max-age=3600` и ETag. Original отдаётся inline; отдельный параметр `attachment` в MVP не нужен.

Контракты синхронизированы с этими решениями в версии `1.0.0`; реализация модулей разрешена после проверки валидатором.
