# Оркестратор агентов для AI Photobank

Это небольшой локальный диспетчер, а не отдельный LLM и не прокси для пользовательского приложения. Он принимает описанные задачи, выбирает CLI и модель по [`policy.json`](policy.json), строит prompt с нужным заданием и запускает исполнителя в отдельном Git worktree. Выполненная работа требует ручного review и merge. Задачи в [`tasks.json`](tasks.json) — стартовый план; перед крупной задачей ее можно разделить на меньшие записи с явными зависимостями.

## Почему правила, а не «AI-начальник»

Для известного набора модулей решение о модели надежнее и дешевле делать по типу задачи и риску. Например, **одна простая миграция** с видом `migration` направляется в GPT-6 Luna, а весь сложный набор схем с pgvector — в более сильный маршрут `backend_complex`. Владелец может выбрать другой провайдер флагом `--provider`; модель внутри этого провайдера все равно выбирает политика. Более дорогую модель имеет смысл вызывать для ревью или отдельно помеченной сложной задачи.

## Подготовка

Нужны Python 3, Git и установленный `codex`/`claude` CLI с рабочей авторизацией. Для параллельного запуска нужен Git-репозиторий с чистым текущим checkout и хотя бы одним коммитом. Оркестратор не создает аккаунты, ключи и не запускает агентов сам по расписанию.

```bash
python3 scripts/orchestrate.py doctor
python3 scripts/orchestrate.py list
python3 scripts/orchestrate.py plan contracts-v1
```

`plan` не тратит токены. Пока `contracts-v1` не принят, зависимые задачи помечаются как blocked.

## Запуск и приемка

```bash
python3 scripts/orchestrate.py run contracts-v1
python3 scripts/orchestrate.py status
```

`run` запускает процесс в фоне и сразу возвращает `run_id`, ветку и путь worktree. Следующие независимые задачи можно запускать так же; два задания с одной зоной владения одновременно не стартуют. Диспетчер записывает prompt, лог, итоговый ответ и состояние в `.orchestrator/runs/<run_id>/` — эта папка игнорируется Git и может содержать чувствительную информацию.

После `needs_review` человек смотрит diff в worktree, проверяет тесты и соответствие контракту, затем коммитит изменения в ветке агента и сливает ее в основной checkout. Только после этого:

```bash
python3 scripts/orchestrate.py accept contracts-v1
```

`accept` проверяет, что ветка действительно вошла в текущий HEAD. Он не делает merge и push автоматически. После приемки разблокируются следующие задачи. Статус `scope_violation` означает, что агент изменил файл вне своего пакета: изменения остаются в изолированном worktree для разбора, а следующий запуск в пересекающейся зоне блокируется.

Если процесс завершился ошибкой, задача получает `failed`; после диагностики ее можно запустить заново. Старый worktree и лог остаются для анализа. Не удаляйте их, пока не разобрали результат.

## Провайдеры

- **Codex:** `codex exec` с выбранной моделью, workspace-write sandbox и JSONL логом.
- **Claude:** `claude --print` с выбранной моделью, без интерактивных approval prompts; команды, требующие подтверждения, могут быть отклонены и должны попасть в отчет агента.
- **Ollama:** выключен по умолчанию. После проверки локальной coding-модели укажите ее ID и `enabled: true` в `policy.json`; запуск идет через Codex CLI `--oss --local-provider ollama`. Ollama разрешен только для перечисленных узких `allowed_kinds`.

Маршрутизация задается в `policy.json`, а объяснение выбора моделей — в [`docs/model-routing.md`](../docs/model-routing.md). Если модель недоступна в вашем аккаунте, диспетчер не подменяет ее молча: используйте другой провайдер или измените политику осознанно.

## Добавление задачи

Добавьте объект в `tasks.json` с уникальным `id`, `title`, `module`, `kind`, `depends_on` и конкретными `instructions`. `module` определяет файлы, которыми можно владеть; `kind` — маршрут модели. Не ставьте в `depends_on` задачи, которые еще не приняты. При работе над новым API сначала добавьте зависимость от контрактной задачи.

Оркестратор проверяет зоны владения **после** работы агента и изолирует изменения worktree. Это полезный контроль конфликтов, но не абсолютная песочница для всех файлов на машине. Не передавайте недоверенному агенту секреты или избыточные права.
